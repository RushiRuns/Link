# P2P Protocol Contracts: Link LAN Messenger MVP

**Date**: 2026-07-27
**Format**: Message-based binary protocol over Noise-encrypted TCP connections.
All payloads described below are the **plaintext** content — they are wrapped in a
Noise_XX encrypted frame before transmission.

---

## Transport Layer

- **Protocol**: TCP (persistent connections per peer pair)
- **Encryption**: Noise Protocol Framework, `Noise_XX` pattern
  - Curve25519 key exchange
  - ChaCha20-Poly1305 AEAD encryption
  - Mutual authentication (both peers exchange static public keys during handshake)
- **Message framing**: 4-byte big-endian length prefix + MessagePack-encoded payload

---

## Message Types (Envelope)

Every message over the wire is a MessagePack object with a mandatory `type` field:

```typescript
interface WireEnvelope {
  type: MessageType;   // string — identifies the payload type
  id: string;         // UUID v4 — unique per message
  ts: number;         // Unix timestamp (ms) — sender's clock
  payload: unknown;   // Type-specific payload (see below)
}
```

## 1. Discovery Protocol (UDP — unencrypted)

Discovery payloads are broadcast/multicast **before** any encrypted channel is established.
They contain **only the minimum information needed to initiate a connection**.

### 1.1 DiscoveryAnnounce

Broadcast/multicast periodically (every 5s) and on app launch.

```typescript
interface DiscoveryAnnounce {
  type: 'discovery.announce';
  deviceId: string;           // UUID v4 — unique device identifier
  displayName: string;        // User's display name
  publicKey: string;          // Base64-encoded Curve25519 public key
  appVersion: string;         // Semver string, e.g. "1.0.0"
  tcpPort: number;            // Port where this peer accepts TCP connections
}
```

### 1.2 DiscoveryResponse

Sent as a unicast UDP reply to a `DiscoveryAnnounce` from a previously unknown peer.

```typescript
interface DiscoveryResponse {
  type: 'discovery.response';
  deviceId: string;
  displayName: string;
  publicKey: string;          // Base64-encoded Curve25519 public key
  appVersion: string;
  tcpPort: number;
}
```

## 2. Connection Handshake (TCP — Noise_XX)

After the Noise handshake completes, peers exchange a `handshake.hello` to confirm
identity and version compatibility before any other messages flow.

### 2.1 HandshakeHello

```typescript
interface HandshakeHello {
  type: 'handshake.hello';
  deviceId: string;
  displayName: string;
  appVersion: string;         // Used for compatibility check (major.minor must match)
}
```

### 2.2 HandshakeAck

```typescript
interface HandshakeAck {
  type: 'handshake.ack';
  accepted: boolean;
  reason?: 'version_mismatch' | 'unknown';  // Present only when accepted === false
}
```

If `accepted === false`, the TCP connection is closed immediately after sending the Ack.
The UI shows the user-readable version mismatch message.

## 3. Presence & Keepalive

### 3.1 Keepalive

Sent every 15 seconds on idle connections. No response required — TCP-level receipt
is sufficient. If no keepalive or other message is received for 30 seconds, the peer
is marked offline.

```typescript
interface Keepalive {
  type: 'keepalive';
}
```

### 3.2 StatusUpdate

Sent when the user's status changes (e.g., user manually sets "Away" in future).
In MVP, only `online` is used — offline is inferred from connection loss.

```typescript
interface StatusUpdate {
  type: 'presence.status';
  status: 'online';  // MVP: only 'online'; offline is implicit from disconnect
}
```

## 4. Messaging

### 4.1 TextMessage

```typescript
interface TextMessage {
  type: 'message.text';
  messageId: string;          // UUID v4, generated by sender
  conversationId?: string;    // Set for 1-to-1 messages
  groupId?: string;           // Set for group messages (exactly one of these)
  content: string;            // Plaintext content (post-decrypt); max 10,000 chars
}
```

### 4.2 MessageAck (Delivery Confirmation)

Sent by recipient immediately on receiving and processing a TextMessage.
This triggers the sender's delivery status to change from `sent` → `delivered`.

```typescript
interface MessageAck {
  type: 'message.ack';
  messageId: string;          // Echoes the messageId of the received TextMessage
  status: 'delivered';        // MVP only has this state; 'read' is not implemented
}
```

### 4.3 MessageTyping (Typing Indicator)

Sent periodically while a user is actively typing a message in a 1-to-1 or group chat.

```typescript
interface MessageTyping {
  type: 'message.typing';
  conversationId?: string;    // Set for 1-to-1 typing
  groupId?: string;           // Set for group typing
}
```

## 5. Group Management

### 5.1 GroupCreate

Sent by the group creator to each invited member individually over their existing
encrypted TCP connection.

```typescript
interface GroupCreate {
  type: 'group.create';
  groupId: string;            // UUID v4 — stable group identifier
  groupName: string;
  members: Array<{
    deviceId: string;
    displayName: string;
    publicKey: string;        // Base64-encoded — so all members can connect to each other
    networkAddress: string;   // Current LAN IP of this member
    tcpPort: number;          // Listening port of this member
  }>;
}
```

After receiving `GroupCreate`, each recipient opens direct encrypted TCP connections
to all other group members they are not already connected to.

### 5.2 GroupMessage

Same as `TextMessage` but always carries `groupId`. Sent individually to each
online group member over their respective encrypted connection.

## 6. File Transfer

### 6.1 FileTransferOffer

```typescript
interface FileTransferOffer {
  type: 'file.offer';
  transferId: string;         // UUID v4
  groupId?: string;           // Set if offered to a group
  fileName: string;
  fileSizeBytes: number;      // Note: for folders, this is an estimate
  mimeType: string;
  chunkSizeBytes: number;     // Fixed at 65536 (64 KB) for MVP
  totalChunks: number;        // Math.ceil(fileSizeBytes / chunkSizeBytes)
  isFolder?: boolean;         // NEW: true if sending a folder
}
```

### 6.2 FileTransferResponse

```typescript
interface FileTransferResponse {
  type: 'file.response';
  transferId: string;
  accepted: boolean;          // true = accept, false = decline
}
```

### 6.3 FileChunk

```typescript
interface FileChunk {
  type: 'file.chunk';
  transferId: string;
  chunkIndex: number;         // 0-based
  data: Uint8Array;           // Raw chunk bytes (encrypted at transport layer)
  isLast: boolean;            // true on final chunk
}
```

### 6.4 FileTransferComplete

```typescript
interface FileTransferComplete {
  type: 'file.complete';
  transferId: string;
  success: boolean;
  reason?: 'cancelled' | 'connection_lost' | 'disk_error';
}
```

## 7. Voice/Video Calls (WebRTC Signaling)

All WebRTC signaling is carried over the existing Noise-encrypted TCP connection.
No external signaling server, STUN, or TURN server is used — all peers are on the same LAN.

### 7.1 CallOffer

```typescript
interface CallOffer {
  type: 'call.offer';
  callId: string;             // UUID v4
  mediaType: 'voice' | 'video';
  sdp: string;                // WebRTC SDP offer string
}
```

### 7.2 CallAnswer

```typescript
interface CallAnswer {
  type: 'call.answer';
  callId: string;
  accepted: boolean;
  sdp?: string;               // WebRTC SDP answer — present only when accepted === true
}
```

### 7.3 IceCandidate

```typescript
interface IceCandidate {
  type: 'call.ice';
  callId: string;
  candidate: string;          // Serialized RTCIceCandidate
  sdpMid: string | null;
  sdpMLineIndex: number | null;
}
```

### 7.4 CallEnd

```typescript
interface CallEnd {
  type: 'call.end';
  callId: string;
  reason: 'user_ended' | 'declined' | 'connection_lost';
}
```

## Error Responses

Any message type may be answered with an `error` envelope if processing fails.

```typescript
interface ErrorResponse {
  type: 'error';
  inReplyTo: string;          // messageId of the triggering message
  code: ErrorCode;
  message: string;            // Human-readable description (not shown to end user)
}

type ErrorCode =
  | 'version_mismatch'
  | 'unknown_group'
  | 'transfer_not_found'
  | 'call_not_found'
  | 'internal_error';
```
