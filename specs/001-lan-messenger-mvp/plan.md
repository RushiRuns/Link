## Summary

Link is a serverless, peer-to-peer desktop messenger for teams on a shared LAN. There is
no central server at any layer — discovery, messaging, file transfer, and call signaling
all happen directly between peers. The technical foundation rests on three pillars:
a layered mDNS + UDP broadcast discovery mechanism, Noise Protocol Framework (Noise_XX)
for end-to-end encryption with TOFU key management, and SQLite + SQLCipher for encrypted
local storage. The UI is built with Electron + React + TypeScript and must follow a
macOS Sequoia-inspired design system with full light/dark support.

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 20 LTS (via Electron)

**Primary Dependencies**:
- `electron` ^31 — desktop shell, main/renderer process split
- `react` ^18, `react-dom` ^18 — UI layer (renderer process)
- `vite` + `electron-vite` — build tooling (already in project)
- `multicast-dns` — mDNS peer discovery (main process)
- `noise-protocol` (or `@stablelib/x25519` + `@stablelib/chacha20poly1305`) — Noise_XX E2E encryption
- `better-sqlite3` — synchronous SQLite bindings (main process only)
- `@journeyapps/sqlcipher` or `better-sqlite3-sqlcipher` — encrypted SQLite at rest
- `electron-store` — config/credentials storage with OS `safeStorage`
- `msgpackr` — MessagePack encoding for wire protocol
- `uuid` — UUID v4 generation

**Storage**: SQLite + SQLCipher (main process) for known-peers; `electron-store` + OS `safeStorage` for identity/private key; OS filesystem for received files

**Testing**: TODO(TESTING_STANDARD) — test strategy not yet defined. To be locked before `/speckit-tasks`. See Quality Gates in constitution.

**Target Platform**: macOS 12+ (Monterey and above), Windows 10+

**Project Type**: Desktop application (Electron)

**Performance Goals**:
- Message delivery < 1 second over LAN (SC-002)
- App launch + peer list populated < 5 seconds (SC-007)
- UI thread never blocked by encryption, I/O, or WebRTC (Constitution Principle I)
- File transfers up to 1 GB without app freeze (SC-004)

**Constraints**:
- All cryptographic work in main process or Node worker threads (not renderer)
- All SQLite I/O in main process via IPC (not renderer)
- Zero internet dependency — no external STUN/TURN/signaling/relay
- No plaintext on the wire — Noise_XX on every peer connection

**Scale/Scope**: ~2–20 concurrent peers on a single LAN; no cloud/internet surface

## Constitution Check

*GATE: Must pass before implementation. Re-checked post-design: ✅ All gates pass.*

- [x] **I. Performance First** — All heavy work (crypto, file I/O, WebRTC encoding) runs in main process or worker threads. Renderer communicates via IPC. File transfer uses 64 KB chunks. No blocking operations on the renderer.
- [x] **II. Native-Feel Design System** — Design system specified: macOS Sequoia-inspired, matte dark-grey dark mode palette, rounded corners, translucency where supported, system typography. Applied via a shared CSS design token system.
- [x] **III. Light/Dark Mode** — OS appearance binding via `nativeTheme.shouldUseDarkColors` in Electron. All components verified in both modes. No pure-black dark surfaces.
- [x] **IV. Security by Default (NON-NEGOTIABLE)** — Noise_XX encryption on every TCP connection from day one. Discovery payloads carry only public metadata. Private keys encrypted via OS keychain (`safeStorage`). SQLCipher encrypts the known-peers database. No unencrypted communication path exists.
- [x] **V. Cross-Platform** — Electron targets macOS + Windows. Platform-specific window chrome handled via `titleBarStyle` per platform. All features must pass quickstart.md Scenario 10 before any milestone is considered complete.
- [x] **Technology Constraints** — Stack: Electron + React + TypeScript. No unapproved substitutions.

## Complexity Tracking

> No constitution violations. No unjustified complexity.

| Decision | Reason | Simpler Alternative Rejected Because |
|----------|--------|--------------------------------------|
| Noise_XX over TLS 1.3 | Serverless P2P; no PKI/CA available | TLS requires X.509 cert lifecycle — incompatible with TOFU, no server to act as CA |
| SQLCipher over plain SQLite | Known-peers keys are a security asset | Plain SQLite leaves public keys readable on disk — violates Principle IV spirit |
| Layered mDNS + UDP fallback | Enterprise Wi-Fi blocks multicast | mDNS-only fails silently in office environments; UDP broadcast is the safety net |
| Main-process-only DB/crypto | Principle I (NON-NEGOTIABLE) | Any renderer-side crypto/I/O would block the UI thread |
